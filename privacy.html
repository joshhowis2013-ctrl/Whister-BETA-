Whister Project Privacy Policy

Operational Architecture Record • Effective 18 October 2026

Whister is an independent, open-source browser fork utilizing the Chromium rendering architecture. We believe software interface design must respect individual privacy boundaries automatically. This operational document registers our zero-telemetry structure constraints, local storage borders, and edge automated routing parameters line-for-line.

1. Zero-Telemetry Local Privacy Model

Unlike conventional web deployment platforms, the Whister browser engine isolates all execution behaviors directly onto the user's local machine layer, actively dropping baseline tracking instrumentation routes completely.

  • No Upstream Metric Streams: Usage indicators, navigation session timings, and crash tracking dumps remain encrypted inside your device filesystem and are never aggregated onto outer networks.
  • Decoupled Profiles: Whister operates with completely decoupled local workspace storage profiles (AppData\Local\Chromium\User Data\). There are no cloud account integrations or personal usage database clusters.
  • Search Query Isolation: When altering providers via the New Tab dropdown widget elements, parameters string chunks are dispatched directly to the chosen engine node (DuckDuckGo, Brave, or Google). Whister functions purely as an analytical bridge and never logs user search keys.

2. Smart Update Loop Validation

To safely deliver engine structural performance increments and source tree tweaks, the native C++ controller layer speaks securely with our subdomains to evaluate file patch availability metrics automatically.

  • Minimalist Check-in Payloads: Clicking version checker inputs prompts WhisterSettingsHandler::TriggerServerUpdateCheck to send a simple, isolated version check string block:
    {"version": "158.0.8105.0"}
  • Ephemeral Edge Validation: Requests drop into high-performance Cloudflare serverless edge runtimes deployed directly at ://whisterbrowser.com. Network address tags (IP headers) are evaluated entirely in volatile server memory caches on the fly to fulfill routing tasks and are never logged to database files.
  • Zero-Egress Hosting Pools: Discovered patch layers (.patch structural diff chunks) and compiled installer stubs (mini_installer.exe) are hosted entirely via encrypted Cloudflare R2 storage assets to guarantee secure download channels.

    Automated Execution Protocol Pipeline

    The internal C++ thread layer coordinates with the network storage layout according to this three-tier execution loop sequence:

    Stage 1: The Request The browser calls WhisterSettingsHandler::TriggerServerUpdateCheck, transmitting a quick payload string container to the staging subdomain:
    {"version": "158.0.8105.0"}
    Stage 2: The Parsing The Cloudflare Edge Beta Worker script interprets the JSON payload, cross-checks version strings, and replies with an update instruction block pointing to the staging patch assets.
    Stage 3: The Deployment The browser client downloads the target chunk asynchronously into the local temp folder and executes the background process silently via base::LaunchProcess.

    3. Cookies & Network Cookies Handling

    Our project directories are engineered strictly as low-overhead, informative developer manifests.

    • No Analytics Cookies: Whister documentation indices do not serve third-party user profile tracking scripts, marketing cookie assets, or audience canvas mapping tags.
    • Open Source Review: Because this implementation runs transparently in the open, users and contributors can trace our core processing parameters line-by-line right inside our public repository file rows at any time.

    4. Third-Party Integrations

    In general, The browser Has been designed to minimize third-party integrations and limit external data exchanges to essential services only.

    However, Use of this website Is subject to certain third-party integrations that may require limited data exchanges for functionality purposes.
